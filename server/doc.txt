Introduction
What This Lab Is About

This lab is a hands-on refactoring lab built around a deliberately poorly structured but fully working application.

The project is functionally correct — all features work as expected — but the codebase contains intentional design, structure, and safety issues spread across multiple layers of the system.

These issues do not cause errors or failures.
Instead, they silently increase:

    Change risk

    Bug probability

    Development time

    Long-term maintenance cost

The goal of this lab is to identify, understand, and refactor those issues step by step, while preserving 100% of existing behavior.
Nature of the Problems in This Lab

The problems in this project are not bugs in the traditional sense.

They are:

    Ambiguous naming

    Mixed responsibilities

    Hidden business logic

    Unsafe dependency direction

    Tight coupling

    Leaky abstractions

    Scattered validation

    Fragile APIs

    Unprotected invariants

Each issue looks reasonable in isolation, which is exactly why such code frequently reaches production systems.

This lab focuses on exposing the long-term cost of these patterns.
Why This Lab Is Important

Most real-world systems:

    Work correctly

    Pass QA and functional tests

    Ship on time

Yet over time they become:

    Hard to modify

    Risky to extend

    Expensive to maintain

    Fragile under change

Refactoring problems are dangerous because:

    They compound over time

    They slow down every future change

    They increase bug rates without obvious failures

    They often force rewrites if ignored too long

This lab trains you to fix design problems early, when they are still cheap, safe, and incremental.
How the Lab Is Structured

The same working application is refactored layer by layer, moving through the system in a controlled sequence.

The lab is divided into the following modules:

    Module 1 — Code Quality & Readability Refactoring

    Module 2 — Backend & API Refactoring (Node.js / Express)

    Module 3 — SQL & Data Access Refactoring

    Module 4 — Architectural & Dependency Refactoring

    Module 5 — Safety & Change-Resilience Refactoring

Each module focuses on a specific class of refactoring problems and demonstrates:

    What the problem is

    Why it increases risk

    How it appears in production code

    How to refactor it safely

    What improves after the refactor

    Why behavior remains unchanged

What You Will Do in This Lab

Throughout the lab, you will:

    Start with working but risky code

    Identify structural weaknesses

    Understand why they are dangerous

    Apply behavior-preserving refactors

    Compare before vs after code

Every refactor is small, intentional, and test-safe.
What This Lab Is Not

This lab is not:

    A rewrite exercise

    A design pattern catalog

    A framework tutorial

    A clean-code style guide

    An opinionated architecture course

Instead, it focuses on practical refactoring decisions that reduce risk in real production systems.

    Refactoring is how you change code safely — not how you make it prettier.
